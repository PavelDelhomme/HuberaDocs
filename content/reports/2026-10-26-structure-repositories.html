Pourquoi le compte de test n’a pas vu le bug

  • Le hardcode Maps (HUBERA_OWNER = Paul + contacts-seed.json) date du 25 sept. 2026 (commit Maps 0.1.11). Les tests labo (Samsung/Blackview/Nothing) tournaient presque toujours avec ton compte Hubera ID déjà piné dans AccountManager / SSO — donc l’UI « Paul » paraissait normale.
  • Le compte QA / Youen n’était pas systématiquement ouvert sur un appareil « vierge » (pas de session Paul, pas de localStorage hérité, pas de seed).
  • Les contacts API sont bien filtrés par user_id : la fuite venait du seed public + identité UI Maps, pas d’un JWT qui donnait les contacts Paul à Youen côté serveur.
  • Sur iPhone (web/PWA) : localStorage.hubera-maps-email pouvait rester à paul@ après le seed/owner, et le toast « Hubera ID · paul@ » s’affichait sans session réelle.

Correctif immédiat : Maps 0.1.127 — purge e-mails owner sans token, login Hubera ID si non connecté, sélecteur Android = session Maps d’abord + déconnexion, seed contacts vide. OTA non forcée.
