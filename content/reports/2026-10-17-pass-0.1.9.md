# 17 oct 2026 — Hubera Pass 0.1.9

Pass ne voyait pas le compte Hubera ID déjà ouvert sur le Nothing, et le déverrouillage par empreinte ne passait pas par BiometricPrompt.

Le compte est lu sur le fil du broker, seulement parmi les apps installées : fournisseur `*.hubera.id` / `*.cloudity.auth`, plus le compte AccountManager `cloud.hubera.id`. S’il y a un jeton, Pass ouvre la session. S’il n’y a que l’adresse, l’écran de connexion la propose. Les autres apps gardent le sélecteur d’avant (`adoptDeviceAccount` reste faux).

L’empreinte est authentifiée par Android (BiometricPrompt). Pass ne stocke pas l’empreinte. Sans empreinte enregistrée, le code de l’appareil, le PIN à 6 chiffres et le mot de passe maître restent disponibles. Une fois le coffre ouvert, le bouton Coffres ramène à la liste. Un coffre vide peut toujours créer un identifiant.

OTA `https://pass.hubera.cloud/updates.json` : **0.1.9** / code **10**, `apkAvailable` true, `forceUpdate` false, `mandatory` false. APK `https://pass.hubera.cloud/apk/hubera-pass.apk` magic `504b0304`, certificat `3cf6c532…`. Un client 0.1.8 voit une version plus récente. Conteneur `hubera-pass-web` inchangé (pas de `down -v`). Nothing non touché.
